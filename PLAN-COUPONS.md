# ПЛАН: «Мои купоны» — хранение ставок пользователей с live-трекингом

> 2026-10-01. Запрос: пользователь принял ставку/экспресс в чате или ленте → она
> попадает во вкладку «Мои купоны» → отслеживается в реальном времени: live-счёт,
> минута матча, статус каждого события (зашло — зелёный / проиграло — красный /
> возврат — серый) — как в реальных букмекерских приложениях.

---

## §1. Что копируем у реальных БК

| Элемент БК | Наша реализация |
|---|---|
| Купон с событиями | Карточка: одиночная ставка (1 нога) или экспресс (2–12 ног) |
| Live-счёт и минута | Для каждой ноги: `2:0 · 67'` из sstats Live-данных |
| Статус события | ✅ Зашло (зелёный) / ❌ Не зашло (красный) / ↩ Возврат (серый) / 🔵 Идёт (синий, пульсация) |
| «Ставка уже рассчитана» до финального свистка | Математический предстатус: ТБ 2.5 при счёте 3:1 → зашло досрочно; ТМ 2.5 при 3:1 → проиграно досрочно |
| Сумма и выплата | Пользователь указывает сумму при принятии → выплата = сумма × кэф |
| История купонов | Список с фильтром по статусу, сворачивание рассчитанных |

## §2. Данные

### Расширение существующих хранилищ (v1 — JSON, без миграции БД)

**predictions.json** (экспрессы, уже есть) — добавить в купон:
```json
{
  "id": "EXP-20261001-001",
  "userId": "usr_...",            // кто принял (из auth), null = аноним
  "amount": 500,                   // сумма ставки (опционально, запоминаем последнюю)
  "status": "pending",             // pending | live | won | lost | void
  "legs": [{
    "gameId": 1631695, "match": "...", "market": "Тотал больше 2.5", "key": "tb25",
    "odds": 1.9, "status": "pending",
    "live": { "score": "2:0", "minute": 67, "presumed": "won" }   // live-слой
  }]
}
```

**signals.json** (одиночные ставки) — те же поля: userId, amount, live-слой в корне.

### v2 — Supabase (при мультипользовательском режиме)
Таблицы `coupons` (id, user_id, type, amount, odds, status, created_at) и
`coupon_legs` (coupon_id, game_id, market, key, odds, status, live_score).
Миграция по образцу 001_users.sql. JSON-хранилище остаётся фолбэком без Supabase.

### Единый API
`GET /api/coupons` — агрегат: одиночные (signals) + экспрессы (predictions)
+ live-данные, отсортировано: живые сверху, рассчитанные ниже. Фильтр: `?status=live|pending|settled`.

## §3. Live-движок (сервер, liveEngine)

1. **Тикер 20 сек** (setInterval в predictions.js/signals.js или отдельный модуль):
   собирает gameId всех pending-ног → одним запросом `/Games/list?Live=true`
   получает текущие счёты и минуты → обновляет `leg.live` (score, minute).
2. **Расчёт статуса ноги:**
   - матч Live → `leg.status = 'live'` + presumed: ставка математически уже зашла
     (ТБ N при тотале > N, Исход при разнице, недостижимой для ничьей в конце) —
     «ставка рассчитана досрочно», как в БК;
   - математически проиграна досрочно (ТМ 2.5 при тотале ≥ 3, аутсайдер отстал на 2
     в компенсированное время — упрощённо: тотал > линии для ТМ) → presumed 'lost';
   - матч Ended → финальный расчёт через outcomeFor() (уже есть).
3. **Статус купона:** any leg lost → lost (немедленно, даже если матч идёт);
   все won → won; иначе pending/live.
4. **Доставка во фронт:**
   - v1: фронт опрашивает `/api/coupons` каждые 20 с (while вкладка открыта,
     document.visibilityState === 'visible');
   - v2: сервер пушит по WS `{t:'bet_update', coupons:[...]}` только при изменении
     (дифф по hash статусов) — мгновенное «✓ Зашло» как в БК.

## §4. UI — вкладка «Мои купоны»

**Куда:** bottom-nav «ТРЕКЕР» → переименовать в «КУПОНЫ» (иконка i-ticket),
сайдбар-пункт «Экспрессы» → «Мои купоны» (там же сводка точности — она и есть
статистика купонов). Старый трекер-модал уходит: его функцию забирает вкладка.

**Экран (сверху вниз):**
```
МОИ КУПОНЫ                                   [live ●N] [флт: Все | Идут | Рассчитанные]
┌─────────────────────────────────────────────┐
│ 🎫 ЭКСПРЕСС · EXP-20261001-002   [🔵 ИДЁТ]  │
│ ─────────────────────────────────────────── │
│ ✅ Тотал больше 2.5        2:0 · 67'   1.9  │  ← зелёный (досрочно зашло)
│ 🔵 Исход 1                 0:0 · 12'   4.3  │  ← синий, идёт
│ ─────────────────────────────────────────── │
│ Кэф 7.49x · Сумма 500 ₽ → Выплата 3 745 ₽   │
└─────────────────────────────────────────────┘
┌─────────────────────────────────────────────┐
│ 🎫 ОДИНОЧНАЯ · СИГНАЛ            [❌ МИМО]  │  ← красная шапка
│ ❌ Исход 1 — Реал — Бетис     0:2 · ФИНАЛ 1.58│
│ Сумма 500 ₽ → возврат 0 ₽                    │
└─────────────────────────────────────────────┘
```
- Цвет шапки купона = статус: зелёная (won), красная (lost), серая (void),
  синяя с пульсацией (live/pending);
- Ноги красятся по индивидуальному статусу; live-счёт обновляется на тике;
- Свёрнутые рассчитанные купоны (details/summary) — история;
- Сводка сверху: активных N, зашло X, мимо Y, ROI по суммам (если указаны).

**Принятие:** в decideBar/decideCard появляется опциональное поле «Сумма, ₽»
(помнит последнюю в localStorage, placeholder — последняя или 500). Принятый купон
→ POST /api/predictions (экспресс) / POST /signals (одиночная) с userId и amount,
тост «Купон добавлен — трекается в „Мои купоны“» + кнопка-ссылка на вкладку.

## §6. Нюансы
- **Чужие матчи не подтягивать**: live-запрос одним батчем (Live=true, 1 страница)
  вместо Games/{id} на каждую ногу — экономно для лимитов;
- **Аноним**: без auth купоны пишутся с userId=null и видны локально у всех —
  приемлемо для текущего режима (один юзер); с auth — разделение по userId;
- **Ретраи/флапы sstats**: тикер не должен падать — try/catch на каждый батч,
  старые live-данные остаются до следующего успеха;
- **Возврат (void)**: точный тотал = линия, отмена матча — серый, кэф 1.0 в расчёте
  экспресса (как в БК: коэффициент купона пересчитывается без ноги) — v2 уточнение;
- Правила ux-ui-rules.md §8/§9: live-статусы не только цветом (иконка+текст),
  скелетоны при загрузке вкладки, empty-state с призывом принять первый купон.
