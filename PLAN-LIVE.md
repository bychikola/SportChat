# ПЛАН: Live Intelligence — «аналитическая платформа» вместо сайта с прогнозами

> 2026-10-04. На основе killer-фишек (Live Prediction Engine, Match Intelligence,
> Value Finder, Track Record, Post-Match Review). Принцип: Data → Model →
> Explanation → Prediction → Live Update → Result → Self-analysis.
> Без «AI BETTING BOT 97% ACCURACY» — только честные вероятности и объяснения.

---

## §0. Сверка с текущим состоянием

| Блок фишки | Статус у нас |
|---|---|
| Prediction Center (карточки 1X2/тоталы/угловые/ОЗ + value) | 🟡 частично: лента считает 1X2 + ТБ/ТМ 2.5; угловые, ОЗ, инд.тоталы — не тянутся |
| Value Finder (сканер market vs model) | 🟡 есть value-колонка и фильтры ленты; нет отдельного режима «найти value» со сортировкой |
| Match Intelligence (форма, xG, H2H, травмы, судья…) | 🟡 лента берёт форму (10 матчей, голы); xG/удары/угловые есть в API (last-games-stats: avgShots, avgOddsXg, avgCorners, avgCards, avgOffsides) но не используются; H2H/травмы/судья — есть в MCP, не в модели |
| Confidence 0–100 от качества данных | 🟡 примитив (объём+value); нет оценки «полноты данных» |
| Live Prediction Engine (пересчёт в моменте) | ❌ нет — главная новинка |
| График вероятности по минутам | ❌ нет |
| «Сценарии»: что должно произойти | ❌ нет |
| Track Record: Win Rate/ROI по рынкам + банкролл | 🟡 «Статистика» считает win-rate из трекера; ROI/банкролл не считаются (суммы уже в купонах); сервер пишет результат — редактирование задним числом исключено |
| AI Post-Match Review (разбор ошибки) | ❌ нет |

## §1. L1 — Match Intelligence: модель на всех рынках и данных (1 сессия)

1. **Расширить extractOdds** (server/feed.js): marketId 8 (Обе забьют), 12 (двойной
   шанс), 45 (угловые), 16/17 (инд. тоталы) — sstats отдаёт все; в вариантах ленты
   добавляются карточки «Обе забьют», «Угловые ТБ 8.5» и т.д.
2. **xG-модель вместо чистых голов**: expectedGoals() уже считает (avgScore +
   avgConceded)/2 — заменить вес: λ = (avgOddsXg + avgScore + соперник.avgConceded)/3
   (xG точнее отражает качество моментов; поля уже в last-games-stats).
3. **Confidence от полноты данных**: данные есть (форма 10, кэфы, xG) → 75–90;
   только кэфы → 40–55; мало матчей формы → −10 за каждый недостающий. Формула в
   одном месте (mk()), честно отображается в ленте и купонах.
4. **H2H в карточку матча** (Match Drawer): sstats_search_matches?bothTeams=… —
   последние 5 очных + исходы; травмы/судья — из Games/{id} при полном разборе.

## §2. L2 — Live Prediction Engine (ядро, 1–2 сессии)

Эндпоинт `GET /api/match/:id/live` (кэш 15с):
1. **Состояние матча**: Games/{id} — elapsed, счёт, statistics (удары/владение/
   угловые/офсайды из потока Pari), события (голы).
2. **Poisson в моменте**: прошло T' минут из 90 → λ_остаток = λ_90 × (1 − T'/90),
   скорректированный на текущую интенсивность: ratio = (xG_факт + удары_факт/10) /
   (xG_ожидание_к_минуте) — давление растёт/падает (как в примере юзера).
3. **Вероятности «сейчас»**: исходы с учётом текущего счёта (П1 при 0:0 и λ_остаток;
   ТБ 2.5: нужно k голов в остатке — Poisson(λ_остаток_сумма) ≥ 2.5 − текущий тотал).
4. **Сравнение с live-кэфом Pari** (pari_match → currentOdds) → live-value.
5. **История вероятности**: сервер хранит снапшоты {minute, p1, px, p2, pTB} на
   каждый тик (data/live-history/{gameId}.json, TTL после матча) → фронт рисует
   график «54% → 59% → 64% → 68% → 72%» (SVG-линия в Match Drawer).
6. **Детект смены сценария**: если |ΔP| ≥ 8% за 15 минут → флаг «🔥 Изменение
   сценария» + причина из дельты статистики (удары/атаки выросли).

Фронт: кнопка «Live» в ленте для идущих матчей (live-матчи в ленту отдельным
блоком сверху) → Match Drawer в live-режиме: график + вероятности + live-value.

## §3. L3 — Сценарии «что должно произойти» (аналитика поверх L2)

Для каждого рынка «если»-текст генерится из Poisson-остатка:
- «Гол до 65-й: P = 58%; если к 60' останется 0:0 → ТБ 2.5 падает до 38%» —
  считаем P(≥1 гол за (65−T') мин) = 1 − e^(−λ') и вероятности при нулевом
  счёте к порогу;
- Топ-2 сценария на рынок → в Match Drawer секцией «🎯 Условия для ТБ 2.5».

## §4. L4 — Track Record (1 сессия)

1. **ROI**: в «Статистике» — таблица по рынкам (сигналы + купоны): Прогнозов /
   Win Rate / ROI (по amounts; для купонов — сумма на купон, выплата при won).
2. **График банкролла**: суммарный банк = старт (суммируем amounts) + последовательные
   результаты по времени расчёта → SVG-линия (как dbar-chart в статистике).
3. **Неизменяемость**: результат купона пишет только сервер (autoCheck/tick) —
   localStorage-журнал остаётся только для причин отклонения. Подпись
   «история ведётся сервером, без правок задним числом».

## §5. L5 — AI Post-Match Review (пол-сессии после L2)

1. Когда купон/сигнал рассчитан lost → в карточке появляется кнопка
   **«🧠 Разбор ошибки»**.
2. Кнопка отправляет в чат готовый запрос: прогноз (рынок, P модели, кэф), финал,
   live-факты (xG, удары, кадры из Games/{id}), «объясни почему модель ошиблась
   и чему это учит: где переоценка, ошибка модели в %».
3. Ответ агента — обычная карточка разбора в чате (у нас уже есть все стили).
4. Разборы сохраняются рядом с купоном (prediction.review) → в «Статистике»
   накапливается база «где модель ошибается».

## §6. Порядок и оценка

```
L1 (рынки+xG+confidence) → L4 (ROI/банкролл) → L2 (Live Engine) → L3 (сценарии) → L5 (Review)
```
L1 и L4 — быстрые и сразу усиливают продукт; L2 — ядро (Poisson-в-моменте +
график); L3/L5 — надстройки. Всё в текущем стеке, без новых сервисов.

## §7. Риски
- live-statistics в Games/{id} есть не для всех лиг — confidence ↓ и график
  по голам/минутам только;
- частота опроса live-матчей: 1 матч = 1 запрос/15с на открытый drawer — ок для
  лимитов; кэш обязателен;
- Poisson-в-моменте груб без xG-потока по минутам — честная подпись
  «оценка по текущей интенсивности», не «точный расчёт».
